# Native cosmetics review — V3
Review-only, no live entitlement or purchase behavior. The route is accessible only via the existing __DEV__ visual QA entry with EXPO_PUBLIC_VISUAL_QA=1 and EXPO_PUBLIC_VISUAL_QA_SCREEN=profile-cosmetics. The approved V3 art registry is deliberately empty in this commit until the binary import is performed; missing art is not an entitlement. Copy the asset-only overlay into the repository root (registry + assets only), never overwrite legacy files or the integrated renderer. Launch from apps/mobile with npm run android (development build), or npm run web for review; the browser-review flag must be off. On Windows PowerShell: $env:EXPO_PUBLIC_VISUAL_QA='1'; $env:EXPO_PUBLIC_VISUAL_QA_SCREEN='profile-cosmetics'; npm run android.
Use one public profile scene, with independent local border/effect selections, all themes, reduced motion, pause, long name, pet and guild toggles, and responsive widths. No profile write or commerce calls. Review fixture uses existing character/pet/scene art. The public renderer ignores QA overrides outside development. The matte is aligned to the outer framed card via negative 8dp inset inside the scene, below all foreground content. Native QA must confirm clipping and layer order, background/resume behavior and low-end performance. Do not merge or release on the basis of a browser mockup.
Next: import and validate exact V3 asset bytes, native screenshots and profiling, then build independently persisted per-character effect selection with account-wide ownership, server authorization, public projection and localization. Store tab remains hidden.
