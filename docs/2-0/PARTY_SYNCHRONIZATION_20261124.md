# Class Synchronization — hidden 2.0 review foundation (24 Nov 2026)

Owner-approved direction: instant, party-wide class affinity/tactical bonuses; all nine base classes have four partners (18 unique pairs). No levels, XP, affinity grind, relationship or guild membership requirements. Both specializations of each base class qualify. No CP effects or matchmaking admission restrictions.

## Implemented
- Versioned, server-side pure catalogue and resolver, unique class pair detection, stable ordering, no duplicate stacking.
- Actual participating character identities must be supplied by a trusted encounter boundary; input roster capped at four and duplicate character IDs/unknown classes rejected. Guild PvE uses a four-member participating subgroup, not an entire guild. Solo and individual World Boss attempts have no effect.
- 1/2/3/4/5/6 active links scale all bonuses to 100/100/80/65/55/50%. Integer basis points and deterministic floor. Provisional synchronization-only caps: +4 percentage points critical chance, 6% damage reduction, 10% for other identical modifier channels. Global engine caps are separate.
- Private unified Equipment/Skills compiler optionally exposes a review plan from the verified build classes and owned equipment runtime character IDs, after compilation. No changes to combat outcomes, equipment evidence, personal CP or default callers. This is not yet authenticated membership proof. Both releaseEnabled and canAuthorizeCombat are false.
- Dedicated catalogue, malformed inputs, duplicate classes, replay, all 36 legal dungeon class compositions, all 495 unordered four-class multisets (including duplicates), and real four-player compile review parity tests wired into hidden CI.

## Required before activation
1. Reconcile with Skills counterplay #1700 and shared 2.0 release branch. Bind to a server-loaded encounter/party roster and versioned membership, class, encounter, seed and ruleset snapshot. For an ongoing encounter freeze the roster at start; refresh at the next encounter boundary after substitutions. Prevent spectators, companions, nonparticipating members and forged or stale identities from counting. Preserve deterministic dungeon replay, persistent HP/cooldowns, group reward authority, and matchmaking role rules.
2. Implement each typed channel in the common 2.0 engine, after base/gear/skills, before appropriate final clamps; keep outgoing and incoming effects distinct. Percentage vs percentage-point semantics must be explicitly matched to existing combat units. In particular armor/ward, haste/accuracy/evasion, penetration, resource regeneration and harmful-effect resistance/stagger require engine reconciliation. Do not convert missing effects into generic damage.
3. Conditional effects: execute only target HP <25%, low-HP damage only source HP <50%, debuffed/shielded target checked at hit resolution; lifesteal scales existing legitimate lifesteal only; do not grant a new proc or double apply DoT, shield or healing. No global guarantees that an extra link always improves actual encounter performance: dilution can reduce a specific stat, and all combat benefits depend on matchup.
4. Model mixed/same-affinity parties, compare equal CP and matched seeded encounters, verify all caps with gear/passives, and tune provisional numbers without making synchronization mandatory. No assumption that nominal total bonus implies effective DPS.
5. Design and obtain owner approval of mobile lobby/recruitment preview, active bonus summary and accessible/localized descriptions. Show all applicable links and effective scaled/capped totals; do not make links a recruitment filter or queue prerequisite.

No runtime integration of bonuses, live routes, DB migration, production/staging writes, UI changes, main merge, deploy or release flag changes. This is an unmounted review-only foundation.

## Follow-up passes: private execution and roster authority
The original foundation above describes the review-only first pass. The new explicit opt-in rehearsal now exercises actual engine hooks; review-only and all default callers remain unchanged.
- New opaque WeakMap-backed token binds exact full compiled input digest, frozen ruleset, encounter/party ID, revision, seed, actor-to-character/class mapping, and independently supplied persisted-scope verifier. It rejects duplicate actor/character identities, mismatches, non-V2 actors, old HP/cooldown persistence and Q-mode legacy profile. Dungeons retain one tank/two distinct damage/one support; flexible modes allow 2–4 participants. No authentication or persistence is implemented by the callback itself. A real service must verify membership, account/character, revision and encounter ownership; never accept client scope, callback, token or numerical bonus. Identical digests can be replayed in QA, not a production reward or encounter settlement authority.
- Explicit private compiler rehearsal checks each scoped character ID/class against the separately verified builds and equipment sources, after compilation. No signed solo trait/enemy kit authority can be combined. Default/no-token and preview-only paths retain previous behavior, and personal stats/equipment evidence remain unchanged.
- 20 of 23 authored channels have experimental engine mappings: outgoing/incoming healing, shield strength, incoming damage reduction, periodic damage, existing lifesteal, physical defense, existing magic ward, critical chance and multiplier, accuracy/evasion rating, physical damage, target execute (<25%), source low HP (<50%), debuffed/shielded target, physical/all penetration and action speed. Physical armor scales shared defense only for physical hits; ward scales existing magical Ward (no free ward without existing Ward); critical chance adds absolute points under the existing 75% cap; critical damage scales base multiplier; penetration adds bypass points under the existing 0–100% clamp; haste multiplies action speed, not cast duration. These interpretations are provisional. Existing lifesteal scales its authored fraction within the 20% cap then healing-received. DoTs scale on resolution only, not application. Source damage factors combine multiplicatively. No unrelated generic damage conversion, no additional proc or player CP. Special secondary effects that bypass normal engine paths (reflect, gem procs, equipment secondary effects, etc.) are not comprehensively integrated or balanced. Signed equipment traits remain solo-only; no persistent dungeon states.

Caps across all equipment/passive layers and full equal-CP battle matrix still require verification.
- Regression source added: scoped verifier rejection, stale scope revision, forged token/class/character, altered seed/order/stat digest, exact replay, damage reduction and shield amount, unchanged personal gear evidence, four-player compiled replay, foreign roster rejection. Production Edge build shim rejects supplied authority; private source and token leakage fence extended. Tests added to hidden CI. Exact-head CI still must pass. ## Follow-up: complete 23-channel private semantics + balance sanity
The three previously unsupported design channels were refined instead of approximated:
- **Mystic Harmony:** `resource_regeneration` becomes **resource generation +10%**. Combat 2.0 resources are discrete trigger-earned stacks, not mana. Each legitimate resource gain accumulates deterministic 1000 bps credit; 10000 bps grants one extra stack when below cap. Bonus grants do not recursively trigger capstones/reactives. Credit is encounter-local in existing proc state and no RNG is added.
- **Mystic Harmony harmful-effect resistance +5%:** enemy-applied DoT coefficients/flats and debuff magnitude are reduced by 5%; duration/tick cadence is unchanged. This avoids a nominal 5% duration reduction deleting an entire periodic tick at interval boundaries. It does not resist buffs, direct damage, boss phase state or cleanse rules.
- **Shattering Force:** the draft `stagger effectiveness +3%` becomes **interrupt recovery +3%** because Combat 2.0 has authored interruptible casts but no stagger subsystem. A successful party interrupt extends that interrupted ability's already-started cooldown by 3% of its authored cooldown. It creates no stun, extra interrupt or new crowd-control category.

All 23 current Synchronization channels therefore have a private engine representation. These semantics remain provisional balance decisions, not release authorization.

New focused tests cover deterministic resource bonus generation, DoT/debuff potency resistance, exact unchanged status duration, and 10.0s -> 10.3s interrupted recovery. A larger sanity matrix runs all **36 standard dungeon class compositions across six enemy pressure profiles (216 cases)** and all **495 unordered four-class flexible compositions** through baseline and synchronized private combat. It verifies immutable personal stat snapshots, finite outcomes, no synchronized damage regression in the controlled fixture and a temporary <35% synthetic damage-outlier guard. This is diagnostic, not a claim that all real encounters or equal-CP boss matchups are balanced.

Still required: exact-head CI, canonical Equipment/Skills #1700 reconciliation, real authenticated/persisted party roster adapter, signed party equipment trait/persistent-state authority, boss-specific equal-CP tuning, global cross-system caps and approved UI/localization. No main merge, public route, DB write, release flag or deployment.
