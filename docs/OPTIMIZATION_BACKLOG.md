**Audit basis:** `main@eb70bb3`, 2026-10-28 · **No implementation.** See [DEEP_QUALITY_AUDIT.md](DEEP_QUALITY_AUDIT.md) for Q01–Q20 classifications and full acceptance records.

## Optimization policy
1. **Measure first:** separate confirmed source characteristics from measured bottlenecks. No startup duration, FPS, memory, query-plan, network p95, AAB weight or battery result was collected during this static review.
2. Preserve the server-authoritative command model, request receipts, transaction boundaries, existing chat feed caching and offline activity semantics.
3. Make one isolated optimization at a time. Capture a before/after trace on the same build configuration, device, save and network profile; revert if no meaningful improvement or gameplay regression.
4. Do not optimize away correctness checks, user feedback, accessibility labels, or essential game-state context.

### O01 — Backend build artifact provenance
- **Observed:** `backend/supabase/functions/coop/index.ts` is empty in the tracked commit; generated by `pnpm --dir backend build:online` according to `backend/package.json` and `docs/implementation/qmode-npc-fallback.md`.
- **Implementation proposal (not performed):** build into a clean temporary output, verify nonzero bytes, lint/typecheck output, smoke `/coop/entry` and Q-Mode start in staging, capture SHA and deploy manifest. Keep rollback bundle.
- **Failure mode:** accidental deploy of empty/stale handler. **Expected benefit:** release safety, not a runtime FPS gain.
- **Acceptance:** build fails loudly when generation is omitted; generated artifact and deployed version are traceable to source commit.

### O02 — Type safety and test health
- **Observed:** `.github/workflows/mobile-core-validation.yml` includes `pnpm typecheck`; latest Q-Mode handoff describes existing starter-companion type errors.
- **Action:** reproduce exact diagnostics in a clean checkout; make one minimal fix PR and add permanent regression fixtures; do not suppress errors or relax `strict` to obtain green.
- **Acceptance:** whole app, core, backend online, migrations and billing checks pass at one Git SHA, with associated job logs.

### O03 — Safe environment isolation
- **Observed:** `apps/mobile/eas.json` points `development` and `preview` to the same project as `production`; separate `staging` exists.
- **Action:** define matrix of profile → API → Supabase project → package/channel → allowed QA actions; use staging for exploratory/test builds and explicitly controlled production smoke. Avoid testing irreversible economy writes on live player data.
- **Acceptance:** known profile can be identified on-device; endpoint assertions fail if a staging build points to production unexpectedly.

### O04 — Reconcile guild contributions
- **Observed:** in `backend/online/gameplay.ts`, guild quest contribution RPC is invoked after a successful gameplay commit and exceptions are discarded.
- **Action:** inspect SQL to determine existing dedupe and compensation. If missing, atomically store intent with authoritative commit, process with stable receipt key, retry asynchronously and monitor dead letters. Do **not** replay complete gameplay actions to repair contributions.
- **Acceptance:** simulated partial failure converges to exactly one contribution, one reward; repeated delivery is harmless.

### O05 — Root presentation clock / derived selectors
- **Observed:** `apps/mobile/App.tsx` ticks every 2s on active Home/Combat, every 15s for other ongoing activities, else 60s; `previewActivityReward`, `companionAttentionSummary`, `equipmentCraftQueueModel`, `eventReadyClaimCount` and navigation counts are derived in root.
- **Hypothesis:** work and child renders occur even when only a progress indicator requires updated time. Not measured.
- **Measure:** Hermes/React DevTools profiler on low-end Android, 10-minute idle/active/resume; collect per-component render count/actualDuration, JS thread occupancy, memory high-water mark and battery proxy. Split based on expensive traces into small memoized selectors or a clock provider used only by active widgets.
- **Guard:** progress bars stay timely; timed rewards remain server-authoritative; navigation badges and timers never freeze at tab switches.
- **Decision:** do **not** memoize the entire app or introduce broad selector infrastructure unless profiling supports it.

### O06 — Native release pipeline and asset budgets
- **Observed:** `apps/mobile/package.json` defines `test:release-bundle` (Expo Android export + `tools/validate-mobile-export-budget.mjs`) but the sampled mobile CI workflow omits it.
- **Action:** validate release export, JS module resolution, asset budget and Android native install separately from fast PR logic tests; record compressed AAB size, install footprint, image decode memory and 10 largest bundled assets. Verify prior Play version upgrades to current versionCode; EAS remote version source and autoIncrement are configured, but device upgrade was not tested.
- **Acceptance:** bundle gate prevents a missing-module commit; AAB boots and upgrades from previous released build; any size increase is explained, not arbitrarily blocked.
- **Do not:** globally downscale pixel-art or equipment icons without comparing rendered clarity.

### O07 — Exactly-once network fault matrix
- **Observed:** gameplay repository and co-op command journal persist in-flight requests; backend uses versioned state and receipts.
- **Action:** inject response loss *before* commit, *after* commit, HTTP 409/429/503, account swap and app kill for inventory sell/withdraw, crafting claim, guild donation, co-op ready/choice/reward.
- **Measure:** count logical requests, backend mutations, receipt replays and unrecoverable pending actions; capture logs without secrets.
- **Acceptance:** one intent → at most one debit/credit; retry is intuitive; pending state survives app restart.

### O08 — Robust HTTP boundary
- **Observed:** `apps/mobile/src/online/{gameplay.ts,coop-client.ts}` call `response.json()` before checking body type/status. `coop-client.ts` does use an AbortController with a 25s deadline and preserves pending mutations.
- **Action:** safely read content type/status, try JSON, limit diagnostic body, distinguish abort/offline/5xx and normalize errors; do not retry POSTs under a new requestId.
- **Acceptance:** mocked empty/HTML/non-JSON responses show a contextual message; a pending command can safely retry.

### O09 / O10 — Local-only persistence reliability
- **Observed:** `src/storage/async-storage-repository.ts` uses one direct JSON key and `App.tsx` may issue unawaited local commits. The online player economy uses a separate server-owned path.
- **Action:** revisioned local commit queue; checkpoint previous valid generation; checksum/migration verification; recovery UI presenting last valid snapshot before destructive reset.
- **Acceptance:** overlapping local writes, injected write failure and damaged JSON recover correctly, without conflating fallback-local with production server state.

### O11 — Transport validation without broad schema rewrite
- **Observed:** Q-Mode projection parser validates only outer structure and uses unbounded `Number()` conversions for version/cursor.
- **Action:** narrow runtime guards for crucial nested fields/finite safe integers and a discriminated error for unsupported server versions.
- **Acceptance:** corrupted sample causes safe error/retry, valid current and previous protocol fixtures still load.

### O12 — Maintainability-focused extraction
- **Observed:** `App.tsx` ~97 KB, `src/core/game.ts` ~111 KB, `InventoryScreen.tsx` ~58 KB.
- **Action:** extract a small command dispatch facade, clock-dependent derived view model and inventory modal state only when tests or profiling show a benefit. Keep public APIs identical and land each extraction independently.
- **Acceptance:** characterized snapshots/command results identical; fewer root render consumers; no effect on network protocol, upgrade or restore.

## Suggested benchmarking protocol
**Device classes:** one low-end Android with constrained RAM; one median supported Android; record model, OS, resolution and refresh rate. **Network:** Wi-Fi, 3G throttle, flaky/offline. **Scenarios:** first launch, guest relaunch, Home→Skills→World→Inventory→Character, 100/500/1000 stack test fixtures where supported, continuous combat timer, chat five rapid channel switches, co-op restart, 30-minute background and reconnect, first/returning event session. **Instrumentation:** Android Studio/Perfetto, Hermes profiler, React Profiler, aggregate request metrics already in `network-request-metrics.ts`, EAS artifact-size report and Postgres EXPLAIN/pg_stat_statements in isolated staging.

For each scenario record `baseline_SHA`, device, data fixture, measured p50/p95 (where meaningful), max memory, dropped-frame %, request count, error rate, before/after delta and guardrail failures. Proposed target thresholds must be approved from a **measured baseline**, not invented here.

## Optimizations to reject until proven valuable
- Faster chat polling, unlimited chat history, aggressive periodic guild refresh.
- Blanket `React.memo` on every component, replacing all state with a new library or rewriting `App.tsx` wholesale.
- Global CDN/image compression that visibly harms pixel-art quality or class/gear legibility.
- Bulk index creation without EXPLAIN and write-amplification analysis.
- Client-side authoritative reward simulation to avoid server latency.
- Excessive network retry loops for mutation endpoints that change requestId.
- Replacing working `FlatList` inventory with a custom nonvirtualized grid.
- Eliminating legitimate pending/confirmation states to shave taps.
