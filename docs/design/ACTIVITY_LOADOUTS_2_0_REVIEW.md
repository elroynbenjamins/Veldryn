# Activity-aware equipment loadouts — 2.0 review

User direction: automatic use of the correct saved equipment loadout when an activity starts, dependent on unlocked slots. Reuse existing character presets, do not introduce a separate inventory. This is design review only; not a new mounted UI, entitlement or runtime change.

## Verified existing implementation
Main's apps/mobile/src/core/character-loadouts.ts uses characterLoadoutSlotCount(state), base 1 + accountEntitlementBenefits().loadoutSlots, bounded by MAX_CHARACTER_LOADOUT_SLOTS=5. Existing v40-preferences-loadouts test documents base 1, VIP or VIP+ each +1, both 3. No entitlement change implied. CharacterLoadoutPreset already stores equipment IDs, exact instance IDs, food and companion. applyCharacterLoadout rejects active combat, checks exact custody, uses immutable candidate and storage constraints. Existing loadout_save/apply/delete are authoritative commands; SavedLoadoutsPanel is already wired. ActivityKind/GatheringSkillId include mining, woodcutting, fishing AND herbalism. Generic start command resolves kind/target server-side; queue_start has separate path.

## Proposed policy
- Five named activity categories Combat, Mining, Woodcutting, Fishing, Herbalism; an unlocked slot may be assigned one category or left manual. At most one assigned automatic preset per category per character. Slots, names and saved items stay character-specific. No new gear copies or capacity.
- Existing entitlement count remains source of truth. Full five-category coverage requires two further slots beyond current standard maximum 3. Recommend earned progression unlocks for remaining slots, exact eligibility/pricing not approved. Never invent or grant entitlements. A base account can choose which category to assign its existing slot.
- Auto-switch toggle per character, explicit category assignment (never guess by label). Legacy unassigned presets remain manual until player chooses. If no matching slot exists, preserve current gear and clearly signal no assigned preset; if leaving gathering for combat without a combat preset, require explicit confirmation/manual equipment selection for interactive entry and pause queued combat with a clear reason rather than silently fight with gathering gear.
- Only server-resolved target/activity kind can select a preset. For ordinary activity changes, settle elapsed previous activity at its original equipment/time, stop it, preflight exact-copy ownership, class/slot eligibility, storage capacity and all required resources, apply entire selected preset atomically, then start next activity and freeze its stat snapshot. A failed assigned preset blocks transition with recoverable reason; no partial swaps or silent fallback. Never restart activity or recalculate previous payouts using new stats.
- Combat includes monster hunts, boss, dungeon, Party Event finale and World Boss. Apply before ready/reservation and compile from the newly verified combat snapshot; never switch frozen raid, dungeon, or party encounter halfway. For background raid use its own exact frozen combat loadout snapshot if supported without disrupting concurrent gathering; otherwise explicit safe transition is required. Protect copies across concurrent custody/reservation.
- Queued and offline progression uses identical authoritative boundary resolver; does not trust a mobile timestamp or preset ID. No effect during processing, faith, travel, training, exploration unless an independently approved category is introduced. Tool tier vault remains independent.
- Preserve exact copy identity, sockets, enhancement, rarity and quality. Gear referenced by any saved preset remains protected from auto-sell/salvage/Market listings. Cannot borrow another character's equipped copy or reuse one item in simultaneous active snapshots without custody policy. Missing copy or locked entitlement is an explicit repair warning.
- Gathering presets change equipment only by default; avoid unintentionally clearing combat food/companion. Existing manual presets keep their current behavior. Combat preset restores explicit combat food/companion subject to authoritative eligibility.
- Compact existing Character > Saved Loadouts panel: activity selector, active icon, Auto-switch toggle, slot count, gear preview and locked slot reason. UI mock approval required before mounting. No loadout system or additional entitlements activated by this spec.
