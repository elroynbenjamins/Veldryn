# Account-wide social profile icon — release checklist

Approved behavior: first-created surviving character's selected portrait seeds the account once; a saved account choice always wins thereafter. Online creation order is public.characters.created_at ASC, id as deterministic tie-breaker, never active or featured order. Local numbered character IDs use their creation sequence. If an old account's first hero has already been deleted, the earliest remaining hero is the only recoverable source. No ownership or gameplay stat changes. Other appearance slots remain per-character.

The state account.profileIconId is canonical. Character profileIconId fields mirror it for legacy mobile, public profile and cooperative projections. Use the existing authenticated, revision-checked gameplay profile/profile_icon commands; no new public write endpoint. Only explicit icon changes publish the local viewer cache after a confirmed command. Remote icon refresh stays batched at 24 hours; a cache namespace bump clears stale pre-migration portraits. New store atlas portraits use the same cropped ProfileIcon renderer in social surfaces.

Release gate: do not merge/deploy the change with a stale Edge bundle. Run mobile typecheck, full core and UX validation, profile-icons regressions, and regenerate both Edge bundles using the canonical build script. Migration 20261125094128_account_profile_icon_first_character.sql generated with the pinned Supabase CLI; temporary generation files removed. Rehearse on staging with first hero inactive/featured alt, account with already selected icon, deletion, simultaneous revision conflict, locked portrait rejection, account switches and a second-device cache refresh. Coordinate production backfill with new Edge deployment and minimum client version; preserve pending receipts and do not overwrite newer committed icon preferences. Backfill is revision-checked and idempotent. No live DB changes made in this implementation pass.

Production read-only coverage check: 372 accounts with a character; 0 missing earliest-character snapshots at inspection time. Recheck immediately before migration; numbers can change.

Review follow-up: wardrobe writes rebase only explicitly edited families onto the latest saved state; the viewer cache rejects icon responses started before a newer confirmed save, and lightweight fallback RPCs cannot erase an icon. The cache uses account identity, not whichever character is active. Added focused regressions for these rules. The temporary Edge generation workflow has been removed after the generated gameplay commit; co-op output was unchanged. Exact-head parity and full CI are still required.
