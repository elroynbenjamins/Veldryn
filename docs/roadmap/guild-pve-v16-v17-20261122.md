# Guild PvE V16–V17 development record (22 November 2026)

**Hidden Veldryn 2.0 draft. No app UI, live API, runtime routing, edge deploy, SQL migration, wallet, gold, token, guild inventory or staging/production data write.** Builds on V15 draft; retain the live Weekly Guild Hunt untouched.

## V16 — trusted private reader / consistent read boundary

Audit: On 22 November the staging Supabase PostgreSQL 17 metadata was read **without inspecting user or game rows**. Confirmed real columns `guild_members(guild_id uuid,account_id uuid,joined_at timestamptz,...)`, `online_game_states(account_id uuid,character_id uuid NULL,state jsonb NULL,revision bigint,updated_at timestamptz)`, `guilds(id uuid,...)`. The existing `public.guild_pve_*` tables belong to Weekly Guild Hunt and **must not** be reused for Broken Forge.

`backend/src/server/combat/guild-pve-authority-v16.ts` is a **port contract**, not a deployable PostgreSQL adapter: a trusted server obtains the authenticated account independently of the command, then guarantees one `REPEATABLE READ` snapshot of account-filtered guild membership, current GameState, frozen roster, versioned expedition ledger and DB UTC clock. The callback enforces:
- Exact authenticated principal match to the read, current guild membership, character owner ID and character ID; positive canonical GameState revision.
- Viewer belongs to frozen expedition roster, joined no later than campaign start (conservative hold; the final late-join policy is still undecided), and is not bound to another guild for that cycle.
- Revision of the private run matches the snapshot's version; no client-chosen revision, clock, stats, materials, companion or class.
- The existing V12 exact forged-copy/equipment/companion verifier creates the combat actor from cloned server GameState.
- Reuse V15 for aggregate progress. Output is **internal only**, no player-identifying roster leakage, and explicitly `canCommit=false`, `canClaim=false`.

**Not yet delivered**: production-ready SQL transaction reader, token freshness/session verification, private expedition tables, Postgres RLS/GRANT review, server deployment or a client API. The injected mock in regression tests simulates the DB snapshot rather than proving its transaction/isolation guarantees. A dedicated auth and SQL review is mandatory.

## V17 — effectful combat, grounded telegraphs (isolated)

`backend/src/server/combat/guild-pve-effects-v17.ts` uses the real `simulateCombat` deterministic engine, current V7 reference/tier system and V13 authored cue metadata. It adds **bounded and explicitly provisional** simulation effects:
- Armoured Warden defense proxy reduced by Gatekeeper and further Armoury clear, with non-negative floor; true armour regeneration is **not** part of this engine yet.
- Seer guardian clear increases final-boss DOT cooldown (lower affliction frequency); Core Stabilizer reduces the exposed-core detonation coefficient; optional Inner Wardens provide a modest exposed defense proxy.
- Shared Pressure applies up to 15% extra final guardian attack, meaningful risk from high aggression.
- Gatekeeper Sunder and Seer curse add short damage-taken debuffs to actual cast effects.
- Rescue and Warding Shrine provide bounded shields, Cleansing Shrine provides a conditional real `cleanse`, Searing Shrine gives a limited exposed-core offensive boost.
- Any simulated protection, cleanse or insight use is returned as a **proposed** charge debit ONLY after a qualifying observed engine event. No durable charge consumption occurs, and no untriggered effect claims a charge.
- All **12 dangerous warning–resolve cue pairs** are mapped to actual authored V13 cue IDs and V7 engine ability IDs. Visible warnings and resolves are emitted only from `cast_start` and `cast_complete` in the real engine events, never fabricated from a script. Interrupted or time-expired casts remain warnings without invented hits.

**Important scope**: The existing V13 catalogue contains **36 authored cues**, but non-dangerous setup/opportunity/recovery beats are not all causal engine events. This V17 pass does **not** yet provide a cross-phase same-action interpreter, proper Warden armour regeneration, persistent pressure/boon charges, all 9 unique optional enemies, 18-node fully battle-ready content or an actual multi-player live raid.

## Deep review gates

1. Exact-head focused V16/V17 compile + deterministic tests must be green before review. All test inputs are fabricated; no real accounts or database rows inspected.
2. Watch for input tampering: never accept raw `tactics` from client JSON. Every cleared objective, shrine selection, and charge count must be authoritatively loaded under the **same** account, guild, cycle and database revision.
3. Preview costs and status effects require a **new atomic V18-style settlement path**: on retry, no extra charge; stale target, no charge; multiple simultaneous actions must serialize shared HP and finite charges.
4. V6 preliminary effort indicates minimum-four HP scaling may disadvantage 1–2 member guilds. Current V17 values are **unapproved QA hypotheses**, not a clear-rate result. Need measured 1/2/3/4/8/12/20 guild scenarios with mixed roles, gear/companion tiers, statuses and sufficient meaningful partial rewards.
5. Review combat and rewards against independent careers in 2.0, taking care not to force combat onto profession-only characters. Other professions can still provide optional supplies via trade or commissioning after later approval.
6. UI design **requires actual theme and mobile-screen approval before any implementation in the real app**. No Guild PvE feature flag, route or scheduled event is enabled here.
