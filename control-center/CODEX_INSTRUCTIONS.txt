DOMAIN INVARIANTS
-----------------
- Gold/currency/item quantities cannot become invalid/negative.
- Prefer delta adjustments; exact-set commands are corruption-repair controls and require stronger safeguards.
- Premium-currency support adjustments preserve explicit support/store reference and do not forge receipt ownership.
- Reward grants/recovery go through current reward receipt/idempotency path.
- Skill XP edits recalculate levels, Combat Level, Total Level and account-wide derived totals.
- Never independently patch derived progression totals.
- Character/Party/Guild rename uses the same profanity/uniqueness/reservation rules as normal gameplay.
- Chat-message moderation preserves evidence; hide/restore rather than destructive deletion.
- External purchase ownership remains receipt-authoritative; manual entitlement is an override layer.
- Pets/backgrounds/borders/achievements/titles respect current account-wide ownership/bonus rules.
- Character skins remain character-specific where the current game requires it.
- Companion duplicate protection, XP, levels/evolution/progression invariants stay enforced.
- Persistent Party remains distinct from Live Dungeon 1 Tank / 2 Damage / 1 Support composition.
- Guild leadership/member constraints remain valid during repair/disband.
- Dungeon cancellation releases queue/run reservations and refunds only verified consumed entry costs.

REDEEM CODE INVARIANTS
----------------------
- Store only SHA-256 code hashes and hints; never persist plaintext codes.
- Do not log plaintext/custom codes in request-body logging.
- Reward bundle must be validated and exist in the real reward registry.
- Enforce starts/ends/global max/per-account max atomically.
- Reward grant uses the reservation idempotency key.
- A crash after reward grant but before status update must not double-grant on retry.

SECURITY
--------
- No SUPABASE_SERVICE_ROLE_KEY in browser/mobile.
- No generic SQL/table editor.
- Every state-changing Control request has explicit admin role authorization.
- High/critical commands require exact typed confirmation.
- Critical registry commands can require approval.
- Optional second-Owner approval: CONTROL_REQUIRE_DUAL_APPROVAL_CRITICAL=true.
- Audit request/approval/cancel/retry/reversal.
- Keep ops_admin_command_events and remote-config revisions append-only.
- Reversal is a new command, not database rewind.
- Protect last enabled Owner.
